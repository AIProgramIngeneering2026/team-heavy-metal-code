# Проверка контракта колодой К1–К10

Контракт: [`docs/api/openapi.yaml`](api/openapi.yaml). Требования: [`docs/requirements.md`](requirements.md). Решения: [`docs/adr/0001-local-tools.md`](adr/0001-local-tools.md), [`docs/adr/0002-background-jobs.md`](adr/0002-background-jobs.md).

## Колода

| Карта | Ответ контракта |
|---|---|
| К1 Двойной клик | Один Job. Повтор с тем же `Idempotency-Key` и параметрами → `200` с прежним `id`; те же ключ, другие параметры → `409 idempotency_key_conflict`. — `openapi.yaml`, `POST /jobs`; `requirements.md` SC-04, AC-10, AC-11 |
| К2 Ответ потерялся | Job сохранён до ответа. Повтор с тем же ключом → `200` с прежним `id`; либо `GET /jobs/{job_id}`. — `openapi.yaml`, `POST /jobs` `200`, `GET /jobs/{job_id}`; `ADR-0002` п.1; `requirements.md` AC-10 |
| К3 Неизвестная операция | Операции нет → `404` от HTTP-слоя; Job не создаётся. — `openapi.yaml` (только `POST /jobs`, `GET /jobs/{job_id}`); `architecture.md` §2 |
| К4 Кривые параметры | `400 invalid_json` (не JSON); `422 validation_error` с `details[].field`/`issue` (ссылка, профиль, длина ключа); `415 unsupported_media_type`. Job не создаётся, GitHub не вызывается. — `openapi.yaml`, `POST /jobs` `400`/`422`/`415`; `requirements.md` SC-05, AC-12 |
| К5 Воскрешение | Запрещено: `done`/`failed` терминальны, перезапуска нет. Новая попытка — новый Job с новым ключом. — `requirements.md` «Жизненный цикл», «Запрещённые переходы»; `ADR-0002` п.7; `architecture.md` §3 |
| К6 Отмена | Не поддерживается. Публичной операции нет; сделанная работа не откатывается. — `ADR-0002` п.7 и «Последствия»; `architecture.md` §3 |
| К7 Огромный вход | тело > 65536 байт → 413 payload_too_large; поле длиннее лимита (repository_url 2048, profile 64, Idempotency-Key 128) → 422 field_too_long с указанием поля. Job не создаётся. — openapi.yaml POST /jobs 413, PayloadTooLarge, 422 (field_too_long), maxLength; requirements.md SC-05, AC-18 |
| К8 Чужой/несуществующий id | Несуществующий → `404 job_not_found`, Job не создаётся. «Чужой» неприменим: аутентификации и владельцев нет; id — UUID; перебор не защищён — граница первой версии. — `openapi.yaml` `GET /jobs/{job_id}` `404`; `requirements.md` AC-07, SC-02 «Граница первой версии»; `ADR-0002` |
| К9 Перезапуск сервера | При старте running → failed(interrupted); обработка не возобновляется; новое задание — новый ключ. created перехватывается заново (блокировка PostgreSQL). — requirements.md «Жизненный цикл», AC-08; openapi.yaml JobFailureCode (interrupted); ADR-0002 п.3, п.6; architecture.md §3 |
| К10 Внешний сервис | GitHub молчит/5xx/таймаут → `failed github_unavailable`; 404 → `repository_not_found`; 429 или 403 с признаками лимита → `github_rate_limited`; прочие 403 → `github_access_denied`. Job `failed`, отчёта нет; клиент видит `failure.code`/`message` в `GET /jobs/{job_id}`. — `requirements.md` SC-03, AC-08, AC-09; `openapi.yaml` `JobFailureCode`, `JobFailed`; `ADR-0001` (сеть — только в адаптере) |

## Что предложил ИИ

**Промпт:** «Вот контракт API (`openapi.yaml`), требования (`requirements.md`) и колода карт К1–К10. Сыграй атакующего: найди три ситуации, на которые контракт не отвечает или отвечает неоднозначно. Для каждой укажи, какой карты это касается и что в контракте отсутствует.»

**Находка 1. `Idempotency-Key` без привязки к клиенту — коллизия между разными клиентами (К1/К8).**
Контракт не говорит, что ключ идемпотентности уникален в пределах клиента; при отсутствии аутентификации два разных клиента с одинаковым ключом и одинаковыми параметрами получат один и тот же Job (`200`), а с разными — `409`, хотя «виноват» не тот, кто первым занял ключ.

**Приняли частично.** В первой версии аутентификации нет, поэтому «клиент» не определён — это граница (`requirements.md`, SC-02 «Граница первой версии»). В `openapi.yaml` добавлено описание ключа; в `ADR-0002` зафиксировано, что ключ глобальный. Отдельного механизма пространств имён нет — осознанно, до появления аутентификации.

**Находка 2. `POST /jobs` с `Idempotency-Key`, который уже связан с `failed`-заданием (К5/К1).**
Если первый запрос завершился `failed` (например, `github_unavailable`), повтор с тем же ключом вернёт `200` и id `failed`-задания — но клиент, возможно, хочет **повторить проверку**. Контракт отвечает: повторной обработки нет, новое задание — с новым ключом.

**Приняли.** Явно указано в `requirements.md` SC-04 п.5 и в «Запрещённых переходах» (`failed → *` запрещён); `ADR-0002` п.7 фиксирует: новая попытка = новый Job и новый ключ. Это осознанное ограничение, а не дыра.

**Находка 3. `GET /jobs/{job_id}` при `job_id` с недопустимыми символами / пустой строке (К8).**
В контракте `job_id` — `string minLength: 1`, но нет ограничения на формат (UUID). Клиент может прислать `../../etc/passwd` или строку в 10 КБ; ответ — `404`, но нет явного `422` для невалидного формата id, и нет лимита длины.

**Приняли.** В первой версии id генерируется как UUID, а поиск идёт по точному совпадению в БД; невалидный формат неотличим от «не найдено» → `404 job_not_found` — это безопасно (нет утечки, нет обхода пути). Лимит длины id не вводим: путь ограничен HTTP-слоем. Зафиксировано в `requirements.md` AC-07 (несуществующий id → ошибка) и в SC-02 «Граница первой версии» (id — UUID). Явного `422` для формата id не добавляем — осознанно, чтобы не раскрывать формат id.

**Итог.** Все 11 карт закрыты. Сознательно не закрыты: К6 — `ADR-0002`; К8 «чужой id» — граница первой версии; К3 — стандартный `404` HTTP-слоя.
