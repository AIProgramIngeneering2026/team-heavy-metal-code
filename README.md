# Проверка учебных репозиториев

Командный проект heavy-metal-code по дисциплине «Программная инженерия».

## Проблема и пользователи

Перед сдачей учебного проекта студенту нужно проверить наличие обязательных файлов и полноту README. Преподавателю приходится повторять эти проверки для множества репозиториев. Ручная проверка занимает время, а отдельные требования легко пропустить.

Сервис предназначен для студентов, которые хотят проверить проект перед сдачей, и преподавателей, которым нужен воспроизводимый отчёт о формальном соответствии репозитория заданным требованиям. Сервис помогает найти нарушения, но не выставляет итоговую оценку за работу.

## Как работает сервис

1. Пользователь через API передаёт ссылку на публичный репозиторий GitHub, идентификатор доступного профиля проверки и ключ идемпотентности.
2. Сервис создаёт задание и возвращает его идентификатор.
3. Сервис получает данные репозитория через GitHub API и выполняет проверки выбранного профиля.
4. Пользователь запрашивает статус задания, а после завершения получает сохранённый отчёт.

Профиль — заранее заданный набор требований: обязательные пути и названия разделов README. Встроенный профиль `basic` проверяет файлы `README.md`, `CONTRIBUTING.md` и разделы README «Описание проекта», «Запуск», «Тестирование».

Отчёт содержит проверенный commit SHA, профиль, итог соответствия требованиям и результаты отдельных проверок: что проверялось, выполнено ли требование, какое нарушение обнаружено. Все проверки одного задания относятся к одному зафиксированному коммиту основной ветки репозитория.

Завершённая проверка может обнаружить нарушения: это результат анализа, а не техническая ошибка выполнения задания.

## Границы первой версии

В систему входят:

- создание задания, получение его статуса и отчёта через сетевой API;
- обработка публичных репозиториев GitHub;
- два независимых вида проверок: обязательные пути и разделы README;
- получение данных через адаптер GitHub API с обработкой отказов;
- хранение заданий и результатов в БД с миграциями;
- автоматические тесты, CI, структурированные логи и health check;
- запуск приложения и зависимостей одной командой по инструкции.

За границами первой версии:

- запуск кода, тестов, сборки или workflow проверяемого репозитория;
- приватные репозитории и другие Git-платформы;
- регистрация пользователей, роли и интеграция с системой оценивания;
- веб-интерфейс, облачный деплой и автоматическая публикация замечаний в GitHub;
- определение плагиата и содержательная оценка корректности программ;
- создание профилей пользователем через API.

## Подключение LLM во втором семестре

Планируется отдельный компонент формирования рекомендаций по содержанию README и результатам формальных проверок. В первом семестре он выдаёт детерминированные рекомендации по шаблонам. Во втором его реализацию можно заменить на LLM через тот же контракт.

Формальные результаты проверок сохраняются отдельно от рекомендаций. Сбой компонента рекомендаций не должен уничтожать готовый отчёт формальных проверок.
